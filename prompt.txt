PROJECT: MITRA

Build MITRA from the ground up as a production-quality AI-powered personal
productivity and life-management platform.

MITRA stands for a Personal AI Companion.

The goal is NOT to build a simple Todo application or a chatbot.

MITRA should eventually understand the user's tasks, projects, goals, habits,
notes, calendar, documents and behavioral patterns and use that information
to provide personalized planning, predictions, recommendations and
decision support.

The core product loop is:

CAPTURE
    ↓
ORGANIZE
    ↓
UNDERSTAND
    ↓
PREDICT
    ↓
SIMULATE
    ↓
DECIDE
    ↓
COACH


===========================================================
1. DEVELOPMENT PRINCIPLES
===========================================================

Build MITRA as a real software product, not as a prototype with fake data.

Rules:

1. Do not create fake functionality and present it as functional.
2. Do not hard-code AI responses.
3. Do not hard-code analytics.
4. Do not expose API keys or secrets.
5. Do not put secrets into GitHub.
6. Do not allow the AI model direct unrestricted database access.
7. All AI actions must go through controlled server-side tools/functions.
8. Every feature must have proper loading, error and empty states.
9. Every database table containing user data must enforce user isolation.
10. Use Row Level Security where applicable.
11. Use migrations for database changes.
12. Keep the code modular and maintainable.
13. Avoid unnecessary microservices.
14. Avoid unnecessary infrastructure.
15. Do not add external integrations until the core application is stable.
16. Do not use mock data in production-facing functionality.
17. If an advanced feature cannot yet be implemented reliably, create the
    architecture/interface for it but clearly mark it as future functionality.
18. Test every major feature before moving to the next phase.
19. After each major phase, ensure the application builds successfully.
20. Commit meaningful changes to GitHub regularly.

===========================================================
24. AI CONTEXT RETRIEVAL
===========================================================

When a user asks MITRA a question:

1. Determine intent.
2. Identify required MITRA data.
3. Retrieve only necessary data.
4. Build structured context.
5. Send context to Gemini.
6. Validate the response.
7. Return the response.

Example:

User:
"What should I work on today?"

Do NOT simply send this sentence to Gemini.

Instead retrieve:

- today's tasks
- deadlines
- projects
- goals
- calendar
- priorities
- historical completion patterns if available

Then provide the context to the model.

Do not build fake "AI/ML" features just to make the UI look impressive.

For example:

with no real calculation.

GOOD:
Calculate a documented score from real activity data.

BAD:
"AI predicts 92% chance of completing task"
with random output.

GOOD:
Use a real deterministic/statistical model and explain the factors.

BAD:
Knowledge graph made entirely of decorative nodes.

GOOD:
Graph generated from actual database relationships.

BAD:
AI says it moved a task but database wasn't changed.

GOOD:
AI generates a structured tool call and the backend actually performs the
validated operation.

55. DEFINITION OF DONE
===========================================================

A feature is NOT complete because its UI exists.

A feature is complete only when:

- UI works
- database works
- API/service works
- authentication works
- authorization works
- validation exists
- error handling exists
- loading state exists
- empty state exists
- responsive UI exists
- tests exist
- production build succeeds


===========================================================
56. FIRST TASK
===========================================================

Before implementing the product:

1. Inspect the repository.
2. Inspect existing files.
3. Inspect current Git state.
4. Create a technical implementation plan.
5. Identify missing infrastructure.
6. Create the application foundation.
7. Configure Supabase.
8. Configure Gemini.
9. Configure environment validation.
10. Create the Next.js application shell.
11. Create a health-check endpoint.
12. Verify database connectivity.
13. Verify Gemini connectivity.
14. Run tests.
15. Run production build.
16. Deploy to Vercel.
17. Verify production deployment.

Do NOT start implementing all MITRA features immediately.

First establish a stable foundation.

After the foundation passes all checks, proceed phase-by-phase.


===========================================================
57. FINAL QUALITY STANDARD
===========================================================

Treat MITRA as a serious portfolio/major-project product.

Prioritize:

Correctness
Security
Maintainability
UX
Performance
AI reliability
Data integrity
Scalability

Do not optimize for the number of features.

Optimize for having a smaller number of features that actually work
end-to-end.

At the end of every phase, report:

1. What was implemented.
2. Files changed.
3. Database changes.
4. Environment variables required.
5. Tests performed.
6. Test results.
7. Deployment status.
8. Known limitations.
9. Recommended next phase.

Do not proceed to the next major phase if the current phase has critical
failures.
